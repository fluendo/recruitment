# Q2.5 — Proposed model for the application

**Model:** YOLO26n-pose, with YOLO26s-pose as alternative if more accuracy is needed.

**Why:**

1. The YOLO-pose family is open source (Ultralytics) and widely used. YOLO26 is the most recent release. [1][2]

2. **NMS-free end-to-end inference:** traditional detection models produce multiple overlapping detections for the same object and require a post-processing step called Non-Maximum Suppression (NMS) to filter redundant ones. YOLO26 produces final detections directly, eliminating this extra step and reducing latency. [3]

3. Up to 43% faster CPU inference compared to previous models. [3]

4. **+7.2 AP on COCO pose benchmark vs YOLO11**, thanks to Residual Log-Likelihood Estimation (RLE) for better keypoint localization. COCO is the standard computer vision benchmark dataset; AP (Average Precision) measures model accuracy — higher is better. [3]

5. Variants available: n, s, m, l, x. I would start with the nano variant for cost efficiency, scaling up to small if keypoints are lost in occlusions or distant players. [2]

6. **Two-stage pipeline:** hit classification would use a lightweight temporal model over a window of keypoints (not frame-by-frame), since hits are temporal events defined by motion over time.

**Validation:** compare n and s variants measuring F1 per hit type, FPS, end-to-end latency, and false positives per minute on real match footage.
