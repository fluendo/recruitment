# Question 6: Improving End-User Experience

## 1. Selective visibility, picked from a list

The operator toggles a tracked person's "stays visible" flag live, from a
list of currently detected/tracked identities. This is the user-facing side
of Question 1's ReID allow-list, and it is not limited to pre-enrollment.

## 2. Region and intensity control

Separate switches for face-only blur vs. depth-based background blur
(Question 2), each with its own intensity, and a choice of style (blur,
pixelation, solid mask). Different products want different privacy/utility
tradeoffs, so this is exposed rather than fixed. Intensity has a minimum that
cannot be lowered, because light blur or pixelation can be partly reversed.
A solid mask is the strongest option.

## 3. Manual override, paired with a short delay

The model will occasionally miss a face or keep the wrong one visible.
Questions 3-4 are about exactly that. The operator gets a live view to
draw or adjust a box directly, backed by a short buffer (a few hundred ms
to a few seconds) before output actually ships, the same technique live
broadcast already uses for delayed censorship. The buffer is what makes
the override usable; without it there's no time to act on it.

## 4. Confidence surfaced, not hidden

Borderline detections (the same ones sitting near the threshold in
Questions 3-4) get a visibly different marker in the operator UI, so a
person knows where to look twice, without needing to understand the model
underneath.

## 5. Presets instead of live reconfiguration

Saved profiles ("interview mode": keep host/guest, blur everything else
by depth; "retail mode": blur every face, no exceptions) are saved versions
of the pipeline config file from Question 5, so the operator picks a mode
instead of reconfiguring every control each session.

## 6. Overrides are logged as an audit trail

Every manual "stays visible" action is logged: who did it, when, and for
which person. The operator also confirms that the person has agreed to stay
visible. This gives Question 1's compliance section its documented decision
without a separate paperwork step. The consent itself has to come from the
person, not from the operator's click.

## 7. Stable, low-delay output

Viewers notice flicker and lag first. When a face is lost for a few frames
(a missed detection, a short occlusion), the blur stays on for a short hold
time instead of switching off, and the box positions are smoothed over time
so the blur does not jitter. The delay buffer from section 3 already allows
this kind of smoothing.
