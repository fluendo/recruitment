# Question 3: Improving Detection Accuracy on Dark-Skinned and Bald People

## 1. Diagnose: measure per subgroup

The detector has a single class ("face"), so there is no confusion matrix
over "dark-skinned" or "bald". Those are attributes of the faces. To see
what is happening we need a test set where each face is labelled with the
attributes we care about:

- skin tone (Fitzpatrick or Monk scale),
- bald or not,
- lighting conditions (and ideally occlusions such as hats and glasses).

The labels can be added to our existing validation set, and an external
set with skin-tone labels (e.g. Casual Conversations, FACET; check their
licences) can be used as a second opinion. Then, at a fixed IoU and
confidence threshold, we report **per-subgroup recall / miss rate**, with
confidence intervals since subgroups are small, and also the intersections
(dark skin + bald + low light), which might be even worse.

This step is not optional: it is the only way to know whether any of the
fixes below actually helped, and whether they hurt the majority group.

Skin-tone labels can count as special-category data, since they can reveal
ethnic origin. Legally we can process processing such data for bias detection 
and correction, but it needs safeguards (limited access, purpose limitation, 
no use at inference).

## 2. Quick mitigation: lower the confidence threshold

Different groups can have systematically different confidence scores
(e.g. around 0.8 for the majority but around 0.6 for bald faces), so a
single threshold tuned on the overall data misses more of the second
group. This is testable: plot the score distribution of the detections
per subgroup.

- If the missed faces have low but non-zero scores, lowering the
  threshold recovers them. Choose it from a **worst-group recall target**
  (e.g. worst-group recall >= 99%), not from the average, and accept the
  extra false blurs as the cost (Consistent with blurring on uncertainty).
- Use one global threshold. A per-group threshold would need an attribute
  classifier at inference, which is a sensitive and biased inference in itself.
- If the missed faces score near zero, no threshold fixes it and the
  problem is in the data or labels (next sections).

## 3. Check the labels

Independently of any imbalance, check the bounding boxes of the affected
subgroup: missing or loose boxes teach the model to ignore those faces,
and adding more images with the same labelling only adds more bad labels.
A cheap way to estimate the problem is to run a stronger detector over the
subgroup images and manually review only the disagreements, which gives
the missing-box rate without re-annotating everything. Fix the labels
before adding data.

## 4. Improve the training data

In order of cost:

1. **Targeted augmentation** of the existing data: exposure, gamma and
   contrast changes (for dark skin under difficult light), and occlusions
   such as hats and glasses (hats hide the hairline, so the model learns to
   find faces without it). Naive hue jitter is not a substitute, since it
   does not produce realistic skin tones. This only varies lighting and
   occlusion; it cannot add new face appearances.
2. **New real samples** for the underrepresented subgroups, from public
   datasets or new collection, with the same labelling checks as above.
3. **Synthetic data** (3D-rendered faces, or generative editing such as
   relighting and hair removal) to add more samples. Boxes come for free,
   but there is a domain gap, so **validation is done only on real data**.

## 5. Retrain without forgetting

Fine-tune on the new data mixed with the original data, to avoid
forgetting the majority group. Additionally use group-balanced sampling
or per-group loss weights, and track worst-group recall next to the
average. Focal loss or hard-example mining can help too, since they put
more weight on hard examples (they work by difficulty, not by group).

Define the acceptance criterion up front, e.g. worst-group recall within a
few points of the best group and above a fixed floor, and re-run the
subgroup evaluation after every change.

## 6. If the gap remains

If the data is balanced and the labels are clean but the gap persists, the
problem is elsewhere (image quality and exposure, preprocessing, model
capacity). Changing the architecture is the last resort, since a detector
that works in general rarely fails on one subgroup only because it is too
shallow. Question 4 covers the case where adding data does not help.
